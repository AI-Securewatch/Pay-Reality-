# Design System Report (Phase 1: Design System Audit)

Audited: typography, spacing, grid, padding, margins, corner radius, colour, elevation/shadows, animation, transitions, icon sizing/alignment, responsive behaviour. Every finding below was verified directly against the code (`grep`, direct reads of `src/styles/theme.css` and every page), not assumed.

## Headline finding: two coexisting design eras

The application was built in two passes with different conventions. The older pass (`src/app/pages/PlatformOverview.tsx`, `src/app/live/pages/LiveAgents.tsx`, `LiveDocuments.tsx`, `LiveEvidence.tsx`, `LiveAssurance.tsx`, `LiveTestIntent.tsx`) used Tailwind utility classes, framer-motion entrance animations, and a 16px (`rounded-2xl`) card radius. The newer pass (`src/app/policy-studio/`, `src/app/ai-policy-builder/`, `src/app/ai-authority-builder/`, 18 files) used inline `style={{}}` objects, no animation library, and a 12px card radius. Both eras happened to share the same `--pr-bg-card` background token, so the visual delta was narrower than it could have been, but it was still real and visible side by side.

| Issue | Reason | Impact | Priority | Implementation |
|---|---|---|---|---|
| Card radius inconsistent (16px vs 12px) across the app, plus one file (`LiveAgents.tsx`) mixing both in the same screen | Two build passes never reconciled their conventions | A careful user moving between Overview and Policy Studio notices the shape change; reads as unfinished | High | **Fixed**: all `rounded-2xl` instances in the 6 older-era files changed to `rounded-xl` (12px), matching the newer convention across the whole app |
| Framer-motion stagger entrance animations exist on only 4 of ~20 pages, with 3 separately hand-rolled implementations of the same fade-up effect | Never centralized into a shared variant; newer pages were built to Policy Studio's own documented "no gimmicks" principle instead | Some pages feel animated and "alive," others feel static, with no consistent rule for which is which | High | **Fixed**: removed the per-item stagger animations from all 4 files (`PlatformOverview.tsx`, `LiveAgents.tsx`, `LiveDocuments.tsx`, `LiveEvidence.tsx`); the app now has one animation posture, not two. The `motion` (framer-motion) package is no longer used anywhere and was removed from `package.json` |
| Zero CSS `transition` on any interactive element across all 18 newer-era files, while the 6 older-era files use `transition-all`/`transition-colors` | The newer pass never carried the transition convention forward | Buttons, links, and inputs in Policy Studio and both AI builders change color/background instantly on hover; feels abrupt next to the rest of the app | High | **Fixed**: added one global base rule in `theme.css` (`a, button, input, select, textarea, [role="button"] { transition: ... 150ms ease }`), so every interactive element in the app now has the same restrained hover transition, with no per-file changes needed |
| Typography: `theme.css` declares `font-family: 'Inter'` and `'IBM Plex Mono'`, but neither font is ever loaded (`index.html` had no font `<link>` at all) | The brand typography choice was never wired up; the browser silently substitutes the OS default UI font | The app has been rendering in system-default fonts the entire time, not the intended typeface; looks fine by accident, not by design | High | **Fixed**: added a Google Fonts `<link>` for Inter (400/500/600/700) and IBM Plex Mono (400/500) to `index.html`, with `preconnect` hints |
| One hardcoded hex color (`#7C3AED`) used twice in `Layout.tsx`'s logo gradient, bypassing the `--pr-*` token system everywhere else | Logo gradient was written before/without a second brand-purple token | A future brand color change would need someone to know to also check this file, not just `theme.css` | Medium | **Fixed**: added `--pr-logo-gradient-end` to `theme.css`, replaced both hardcoded occurrences |
| No `:focus-visible` styling anywhere in the app, and 9 inputs explicitly set `outline-none` | Never added; browser default focus rings were being suppressed on those 9 inputs with no replacement | Keyboard users tabbing through any form in the app cannot see which field is focused | High | **Fixed**: added a global on-brand focus ring (`outline: 2px solid var(--pr-authority-blue)`) to every interactive element via `:focus-visible`, and removed the 9 `outline-none` classes that would have suppressed it. Full detail in `ACCESSIBILITY_REPORT.md` |
| Responsive behaviour is minimal: 9 total responsive-breakpoint (`sm:`/`md:`) usages across the entire app, concentrated in `Layout.tsx`'s mobile drawer | This is a desktop-first internal enterprise console (matching Stripe's/Linear's own admin surfaces), not a consumer app; full mobile layouts for 8+ complex data-entry pages were never built | Policy Studio's forms, tables, and the Authority Graph's 4-column summary strip will not reflow gracefully below tablet width | Medium | **Deferred, documented**: a full responsive retrofit of every grid/table (12+ files) is a larger, separate effort than a polish pass; noted here honestly rather than silently left unaddressed. The one cheap win already in place: `Layout.tsx`'s sidebar already collapses to a drawer below the mobile breakpoint |
| A second, fully generic shadcn/ui theming system (`--background`, `--foreground`, `--card`, a `.dark` class, oklch color values) coexists in `theme.css` alongside the real `--pr-*` token system | Left over from the initial component-library scaffold | Looks like dead CSS at a glance | Low | **Investigated, not removed**: confirmed via `grep` that `src/app/components/ui/sheet.tsx` (the mobile nav drawer) actually uses `bg-background`/`text-foreground`, so this is live, load-bearing CSS for one component, not waste. Removing it would require re-skinning `sheet.tsx` to the `--pr-*` tokens directly, a real but separate follow-up |

## What was already consistent (no fix needed)

- Icon sizing already follows a sensible two-tier scale (`w-4 h-4` for primary icons, 16 uses; `w-5 h-5` for secondary, 8 uses), not chaotic.
- Primary action buttons (`px-4 py-2 rounded-lg text-sm font-medium`) are already identical across both design eras; the one exception (the homepage hero CTA, slightly larger at `px-5 py-2.5 rounded-xl`) is a deliberate, defensible size bump for the single most prominent call-to-action on the app, not an inconsistency.
- The three data tables in the app (`PolicyListPage.tsx`, `UploadPage.tsx`, `CorpusUploadPage.tsx`) already used identical header/row/border conventions before this pass; only their missing hover feedback needed fixing (see `VISUAL_CONSISTENCY_REPORT.md`).
